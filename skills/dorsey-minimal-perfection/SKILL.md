# Dorsey Minimal Perfection

This name reflects the user's interpretation of Jack Dorsey's approach, not a verified quotation or official methodology. Do not invent attribution.

Minimize the number of decisions the audience must process. Give the remaining details deliberate attention. Perfection means meeting the chosen artifact's intent and observable acceptance criteria, not eliminating every possible criticism.

## Workflow

1. Identify the actual outcome and stage: experiment, demo, public release, or production product. Read or inspect the existing artifact before prescribing changes. Ask only for missing inputs that materially block progress.
2. State the single experience the audience should have. Select the few details that carry it, usually one to three. Preserve distinctive elements the user loves even when they are unusual or imperfect.
3. Separate essentials from deferrable embellishments. Remove or defer additions that do not serve this release. Never remove accessibility, safety, truthful credits, rights checks, or core functionality as decorative overhead. File deletion and publication still require their own authorization.
4. Define a concrete quality bar for each essential detail. Prefer observable criteria over adjectives such as premium or perfect. Use the user's taste for artistic choices and tests for functional claims.
5. Refine the highest-impact deficiency first. Work within the user's time and spending limits. If none exist, propose a small first pass rather than an unlimited polish loop. Do not buy tools or generate paid batches without authorization.
6. Inspect the result in its actual medium: listen to audio, watch video with sound, read prose aloud when useful, or exercise the primary app flow. State what was and was not verified.
7. Stop when the essential criteria pass. List unresolved nonblocking improvements separately. Prepare the release artifact or next concrete action; do not turn a request for advice into automatic posting, deployment, or messaging.

## Response Shape

Keep the response proportional to the project:
- Core: the one intended experience.
- Keep: the essential details and each one's quality bar.
- Defer: distractions outside this release.
- Ship when: a finite acceptance condition and the next action.

Do not require this format when a short paragraph is clearer. Do not mistake minimalism for a universal visual style, arbitrary shortness, or deleting useful complexity.

## Example: First AI Music Reel

Core: make a listener want to replay one musical passage.

Keep:
- One owner-selected excerpt: preserve the emotional moment, intelligible words, and an intentional beginning and ending.
- One coherent visual idea: a consistent subject and setting, no distracting morphing, movement that supports the music.
- One readable identifier: correct artist and song title, within platform-safe placement.

Defer: a complete fictional universe, four character introductions, full-length film, distributor setup, API integration, and extra software subscriptions.

Ship when: a short vertical export plays correctly with sound, the owner likes the combined result, captions fit, and permissions/disclosures are checked. A demo can be labeled as a demo. Missing audio is an input dependency, not a reason to invent a track or substitute an unapproved recording. The owner performs any personal social posting required by their standing instructions.

Audience feedback informs the next iteration; it does not retroactively invalidate the user's enjoyment. Optimize for a finished intentional artifact, not a guarantee of approval or virality.
