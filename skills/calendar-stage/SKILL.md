# Calendar stage

Give the artifact a stage and a slot: who it serves, where it belongs, what form it takes, and when it should appear.

Inspect the artifact, project instructions, current publishing surfaces, and the user's actual cadence. Distinguish a seed, working sapling, finished artifact, and verified delivery. Identify the intended reader/listener/user benefit and the quality floor for that stage. Preserve the user's chosen destination unless evidence supports a reason to reconsider.

Choose one primary home that fits the artifact and one optional discovery surface. Explain each role. Examples: a complete essay at an owned blog; a short excerpt on an existing social profile; a song on an existing music release surface; a demo at the product's real URL. Verify that the surface exists and supports the format before making specific platform claims. Use primary documentation for changing limits and rules. Do not invent channel names or URLs.

Recommend an exact next date, time, timezone, format, and cadence. Use the user's timezone and preferred time notation. A precise slot is an operational choice, not proof of optimal audience reach. If audience analytics or availability are absent, label the slot a trial, explain the assumption, and state what evidence would change it. When the user asks for calendar-fit timing and calendar access is available, inspect availability without exposing unrelated event details. Never claim a slot is free without checking it.

Use the smallest sustainable schedule that serves the user's goal. Separate production cadence, publication cadence, and curation cadence. Keep a fallback for a missed slot and avoid turning a backlog into a mass-publishing instruction. For time-sensitive artifacts, check the real event/deadline and prioritize relevance over habitual slots.

Output a compact stage card or calendar table with artifact ID, readiness, primary destination, optional discovery destination, exact proposed slot, timezone, cadence, why this fits, required next action, and confidence/evidence. Include the definition of shipped and a receipt field. If ranking a queue, tie readiness to actual material and preserve source provenance; do not equate a generated title or a metadata score with quality.

Separate recommended, approved, scheduled, and shipped states. Creating this plan does not create calendar events, enable reminders, publish, or communicate as the user. Use the actual calendar/automation tools only when the user requests those actions. Existing personal-communication restrictions still apply. Keep private source material in private storage and show only reviewed excerpts on public stages.

Run the skill by producing the stage card and proposed calendar for the current artifact or ranked queue, with links to the real work. Prefer a useful local interactive view when comparing several artifacts or slots. Report missing source coverage and timing uncertainty plainly.
